# Phase 4.2 Financial Position Boundary

## Goal

Make `MTLedger.getFinancialPosition()` the canonical owner of financial-position composition, including committed credit-installment liabilities, while preserving the public `App.getFinancialPosition()` adapter and its existing return shape.

## Scope

This slice moves only the domain calculation that currently lives between `App.getFinancialPosition()` and `MTLedger.getFinancialPosition()`:

- `MTLedger.getFinancialPosition()` accepts `transactions` and `rewardForTx` dependencies.
- The Ledger service derives committed installment liabilities from future (not-yet-posted), non-excluded credit-wallet transactions, matching the existing `getCommittedInstallmentDebt()` contract.
- Expense amounts for that derivation use the same non-persisted ledger amount semantics as the existing `_expectedLedgerAmountForTx` path (`preferStored:false`).
- `App.getFinancialPosition()` gathers runtime state and passes dependencies to Ledger.
- Category buckets (`cash`, `investment`, `gold`, `fcd`) remain in App because they are presentation-oriented groupings.

## Contract

`MTLedger.getFinancialPosition({
  wallets,
  loans,
  transactions,
  today,
  cryptoValue,
  rewardForTx,
  committedLiabilities,
  walletValue,
  excludeWalletTypes,
})` retains the existing return fields and behavior.

When `committedLiabilities` is omitted, the service computes it by summing `getCommittedInstallmentDebt()` for every non-excluded credit wallet. The transaction amount resolver uses `getLedgerAmountForTx(tx, { wallets, rewardForTx, preferStored:false })`. An explicit `committedLiabilities` value remains supported for compatibility and takes precedence over derived values.

Posted transactions, non-credit wallets, and excluded credit wallets do not contribute to committed liabilities. Existing crypto exclusion, loan receivable, wallet liability, and net-worth semantics remain unchanged.

## Non-goals

- No new runtime module or HTML load-order change.
- No removal of `App.getFinancialPosition()` or `Calc.getNetWorth()`.
- No change to category-bucket semantics.
- No Supabase schema or Edge Function changes.

## Verification

- Direct Ledger tests prove derived installment liabilities, posted-date filtering, excluded-wallet filtering, and reward-adjusted expense amounts.
- A static architecture test proves App delegates the liability composition to Ledger instead of calling `getCommittedInstallmentDebt()` itself.
- Full Node regression suite, syntax checks, and `git diff --check` must pass.

# Phase 4.3 Persist Hook Boundary

## Goal

Remove one proven-redundant `App._beforePersistV50` wrapper chain by keeping the upcoming-bills normalization and V5 migration in one canonical persist hook.

## Current issue

The upcoming-bills feature assigns a wrapper to `App._beforePersistV50` near the top of `app_v2.js`, while the main `persist()` implementation assigns `App._beforePersistV50` again later. The later assignment overwrites the first function, so the source contains a misleading patch chain and the wrapper's ordering is not durable.

## Design

- Keep exactly one `App._beforePersistV50` assignment.
- Define it next to `migrateToV5()` inside `persist()` where the migration hook is owned.
- Run `migrateToV5()` and `ensureUpcomingBillsState()` from that canonical hook.
- Preserve `getStateCommit().beforeCommit` as the caller of `App._beforePersistV50`.
- Do not change storage keys, commit ordering, or migration behavior.

## Non-goals

- No changes to other UI wrappers or screen hooks.
- No change to upcoming-bill persistence APIs.
- No storage schema or Supabase changes.

## Verification

- A static architecture test proves there is one assignment and that the canonical hook calls both normalization functions.
- Existing upcoming-bill, state-commit, and full Node tests remain green.
